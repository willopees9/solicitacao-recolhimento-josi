# NFD Only Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove Nota Fiscal from the request flow and make NFD the only active duplicate key.

**Architecture:** Keep the existing database alive by adding a forward migration. The application stops accepting or showing `notaFiscal`, while the database keeps the old `nota_fiscal` column as an internal compatibility field.

**Tech Stack:** Next.js 14 App Router, React 18, TypeScript, Zod, Supabase PostgreSQL/RLS.

## Global Constraints

- Do not reintroduce automatic drafts.
- Do not rebuild the existing Supabase database from old migrations.
- Do not expose Nota Fiscal in the UI.
- NFD is the only fiscal duplicate key.
- Rejected requests do not block reuse of an NFD.
